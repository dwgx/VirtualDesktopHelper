# 03 — 根因分诊：用户说「头显连不上 / 找不到 PC」时按什么顺序查

配套：`01-ports-and-discovery.md`（事实）、`02-pc-checklist.md`（27 个检测项，本文引用其编号）。

## 核心心法：先分清「PC 没广播」还是「广播了但到不了」还是「到了但连不上」

这三个阶段的分界点是 **UDP 38850 / 38860**：

```
        ┌─────────────────────────────────────────────────────────┐
        │  阶段 A：PC 自己没跑起来                                  │
        │  → 零广播、零监听。PC 侧全部检测项都会显示「正常」，       │
        │    这是最贵的误诊来源。                                   │
        ├─────────────────────────────────────────────────────────┤
        │  阶段 B：PC 在广播，但包出不去/被吞                       │
        │  → 有广播无回应。网卡/路由/杀软/AP 隔离。                │
        ├─────────────────────────────────────────────────────────┤
        │  阶段 C：包到了，TCP 连不上                               │
        │  → 38810-40 监听在但握手失败。防火墙 profile / 端口占用。 │
        └─────────────────────────────────────────────────────────┘
```

**一句话判据**：让用户打开 Streamer，同时在本机抓 `udp dstport==38860`。
- 一个包都没有 → 阶段 A
- 有本机发出的包、头显收不到 → 阶段 B
- 头显收得到、回不来 → 阶段 C

## 分阶段清单（可直接照着念）

### 阶段 0 — 「PC 根本没在广播」（成本最低，必查）

| 顺序 | 清单编号 | 查什么 | 失败结论 |
|------|---------|--------|---------|
| 1 | **#1** | `VirtualDesktop.Streamer` 进程在不在 | 没进程 → 一切免谈，先启动 |
| 2 | **#2 / #19** | 38810-40 是否 Listen，PID 是否是 Streamer | 有进程无监听 → Streamer 初始化失败 |
| 3 | **#3** | `ServiceLog.txt` 里的 `-2147024891` | 服务身份错 → 人工重装，工具不碰 |
| 4 | **#4** | `LastConnectDate` / `ShowPairingRequests` | 从未连过 / 配对请求被关 |

> **这一步为什么排第一**：本机实测（01 文档 §5.4）`VirtualDesktop.Service` 状态是 `Running`，
> 但 `ServiceLog.txt` 里 2026-09-07/09-14/09-18 反复记录
> `UnauthorizedAccessException: ... configured identity is incorrect`。
> 这种状态下**服务看起来健康，但 PC 上没有任何监听和广播**，
> 而阶段 1-4 的所有网络检测项**全部显示正常**。
> 不先查这一层，就会把大量时间浪费在防火墙和路由器上，而真正的原因根本不在网络。

### 阶段 B — 「PC 在广播，但包出不去」

| 顺序 | 清单编号 | 查什么 |
|------|---------|--------|
| 5 | **#11** | `pktmon` 抓 60 秒，看 `udp dstport 38860` 有没有本机发出的包 |
| 6 | **#13 / #14** | APIPA 网卡（**务必排除 `Local Area Connection*`**，本机 5 个 APIPA 里 2 个是伪连接） |
| 7 | **#16** | 虚拟/VPN 网卡（Hyper-V / WSL / VMware / TAP / Wintun） |
| 8 | **#17** | `InterfaceMetric` 排序 —— 广播是否走物理 LAN ⚠ **高风险，只诊断** |
| 9 | **#18** | ICS（`SharedAccess`）是否 Running ⚠ **高风险，不自动停** |
| 10 | **#5-#7** | 防火墙规则存在性 / profile 覆盖 / Program 路径有效性 |
| 11 | **#8 / #10** | Defender profile 开关 + 第三方杀软 |
| 12 | **#12 / #15** | `DontWarnApps` 里的 `NetworkProfile` + `NetworkCategory` 是否 Public |
| 13 | **#23** | PC 是否在用无线（官方要求有线 + 5 GHz） |
| 14 | **#24 / #25 / #26** | 网卡节能 / 睡眠唤醒 / 换 IP 未恢复 |

### 阶段 C — 「包到了，TCP 38810 连不上」

| 顺序 | 清单编号 | 查什么 |
|------|---------|--------|
| 15 | **#15** | 当前 profile 是 Public 吗 |
| 16 | **#9 / #11** | 出向被 Block？UDP 被 WFP 驱动过滤？ |
| 17 | **#19 / #20** | 38810-40 / 38850 是否被别的进程占 |
| 18 | **#10** | 第三方杀软 |
| 19 | **#21** | 是否误以为需要 UPnP（同网段不需要） |

## 工具能自动修 vs 只能解释 —— 明确划分

### ✅ 能自动修（都有确定回滚，共 6 项）

| 清单编号 | 修复动作 | 回滚 |
|---------|---------|------|
| **#1** | `Start-Process` 启动 Streamer | `Stop-Process -Id <Pid>` |
| **#5** | 新建入站规则 | `netsh advfirewall firewall delete rule name="Virtual Desktop Streamer"` |
| **#6** | 规则 profile 补齐 | 先 `findstr /i profiles` 记原值 → 改回 |
| **#7** | 删除指向失效路径的规则并按实际路径重建 | 先删后建 = 天然可回滚 |
| **#13** | `Enable-NetAdapter`（**仅当用户此前手动禁用过**） | 反向 `Disable-NetAdapter` |
| **#24** | 电源计划 standbyidle 复原 | `powercfg /setacvalueindex scheme_current sub_sleep standbyidle <原值>` |

> 注意：即使是这 6 项，**#13 和 #24 也必须先记录原值**，且 UI 上要求显式确认。

### ⚠️ 高风险 —— 工具只诊断、绝不自动执行（4 项）

| 清单编号 | 为什么不能自动做 |
|---------|----------------|
| **#15** 改 NetworkCategory | 把 Public 改成 Private 会放宽**整张网络**的入站信任，是用户的安全姿态变更 |
| **#17** 改 InterfaceMetric | 影响全局路由，可能同时打断 VPN 和所有出站流量 |
| **#18** 停 ICS | ICS 常在给手机开热点，停掉会断掉别人的网络 |
| **#13** 禁用网卡 | 可能禁用掉正在承载远程会话的那块网卡 |

### 🖐 只能解释 + 给固定指引文案（PC 侧无观测点）

| 问题 | 为什么工具管不了 | 给用户的话（文案要点） |
|------|----------------|---------------------|
| 路由器 AP 隔离 / Client Isolation | Windows 读不到自家路由器的这个开关 | 「在路由器管理页关闭『AP 隔离/访客隔离/Client Isolation』」 |
| 访客网络 Guest Network | 同上 | 「PC 和头显都退出访客网络，接到同一个主网络」 |
| VLAN | 同上 | 「确认两端在同一个 VLAN/网段」 |
| 2.4 GHz 与 5 GHz 是否同网段 | 取决于路由器实现，无统一答案 `[未验证]` | 「建议两端都连 5 GHz；部分路由器会为双频拆分网段」 |
| 路由器 UPnP / 端口转发 | 只在远程场景需要 | 「同网段不需要端口转发；要用远程连接才开 UPnP 或手动转发 TCP 38810/38820/38830/38840」 |
| NAT 类型（Full cone / Open NAT） | 需路由器或 STUN 服务器才能测 | 「若路由器有 NAT 类型选项，选 Full cone / Open NAT」 |
| 头显侧的 Wi-Fi 设置 | 不在 PC 上 | 「在头显的 VD 设置里确认连的是 PC 用的那个路由器」 |

### 🚫 绝对禁止（硬地板）

| 清单编号 | 禁止理由 |
|---------|---------|
| **#10** 自动禁用第三方杀软 | 安全软件属用户自主决策；官方 FAQ 也只是让用户「try disabling」。工具自动禁用 = 制造安全风险 |
| **#19 / #20** 自动结束占位端口的进程 | 可能是用户的正经业务进程，且「杀 chrome/codex/omp」在硬地板上被明确禁止 |
| **#3** 自动重装 Streamer 服务 | 会改服务登录账户与防火墙规则，必须人工确认 |
| 任何项 | 自动开启系统防火墙 / 自动开 UPnP | 扩大攻击面，属安全姿态变更 |

## 三条判错预警（本轮实测踩到的）

1. **「规则存在」≠「防火墙开着」** —— 本机 `Private`/`Public` profile 全 `False`（01 文档 §5.2），
   但 `Virtual Desktop Streamer` 规则存在且覆盖三 profile。这两个是**独立**的检测项，必须分开判。
2. **「服务 Running」≠「Streamer 在跑」** —— 见阶段 0 第 3 项。
3. **「`Get-NetAdapter` 没有」≠「这个网卡不存在」** —— 本机 `Local Area Connection* 2 / * 5`
   两条 APIPA 伪连接在 `Get-NetAdapter` 里完全不可见，只有 `Get-NetIPAddress` 看得到（#13 / #14）。

## 工具实现建议：一次跑完 vs 交互式

- **首屏「一键体检」**：跑阶段 0 全部（#1-#4）+ 阶段 B 的只读项（#13/14/16/17/18 + #5/8/10/15）。
  这 13 项全部是只读 PowerShell，总耗时应在 3 秒内，**不需要管理员权限**（除 #11 抓包）。
- **「深度体检」**：加 #11 抓包 + #19/20 端口占用。需要管理员。
- **修复按钮**：只对 ✅ 那 6 项显示可点的「修复」，每项都必须在按钮旁显示**将要执行的命令**
  和**回滚命令**，让用户能自己复核。
