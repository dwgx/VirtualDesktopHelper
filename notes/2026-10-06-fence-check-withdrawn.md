# 栅栏检查：写了、被真实文件推翻、没有上线

2026-10-06。

## 想解决什么

今天把 README 的代码栅栏弄坏两次。**两次的检查都通过了**——
`check-symptom-map.ps1` 校验 README 的强调标记和数字，**而栅栏坏掉时那句话就进了代码块，
强调检查根本看不见它**。表现是四个字面星号。

想加一道「反引号围栏数量必须是偶数」的检查，三行就能写。

## 写完拿真实文件一试，它就垮了

`docs/report-export.md` 报「3 个围栏，奇数」。去看了，第 29 行是：

> 围栏长度按内容里最长的连续反引号自动加长，机器输出里出现围栏标记也关不住代码块。

**那是故意写的行内示例——它就在讲这件事。三处里只有两处是栅栏。**

换成开合状态机也不行：**在语法上，「正文里举例」和「忘写闭栅栏」是同一个 token**，
没有任何解析方式能把它们分开，而不引入新的误判。

## 所以撤了

**理由和同一天早些时候那次 `check-emphasis.py` 完全一样**：会误报的闸门比没有闸门更糟。
它教人忽略红色，而这个项目今天已经因为 CI 静默不跑整整浪费了一小时。

**两次都是同一个决定：写了，跑真实数据，被推翻，撤掉。**
区别是那次我自己发现，这次是拿 `docs/` 里现成的文件试的——**试的对象必须是真实数据，不能是我构造的样例。**

## 顺带被绊的两次

**① 打印了 FAIL 却没加进退出条件。**
一道打红字然后 `exit 0` 的检查比没有检查更坏，因为 **CI 会显示绿色**。

**② 两次编辑各加一层 BOM，叠成三层**，PowerShell 直接解析失败。
**这是同一天第四次犯同一件事**，而我已经写过一条专门讲它的 note。
**写过不等于会做**——note 记录的是教训，不是肌肉记忆。

## 留下的

栅栏断裂今天发生两次、修好两次，**而能自动检查它的方法不存在**。
这条写在这里，比塞进一个会误报的闸门诚实。
