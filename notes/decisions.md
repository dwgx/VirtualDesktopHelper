# decisions — 架构决策记录（ADR）

## ADR-001 技术栈：C# / .NET 10 WPF

**状态**：已定（2026-10-05）

**背景**：Owner 要 UI 观感对齐官方 `VirtualDesktop.Streamer.exe`，那是 WPF + `Xceed.Wpf.Toolkit`。
本机 `dotnet` SDK `10.0.400`，`Microsoft.WindowsDesktop.App 10.0.11` 已装（实测）。

**决定**：新工具 = `net10.0-windows` WPF。不用 WinForms（旧 VDH 是 WinForms，控件观感跟不上目标 UI）。

**后果**：自包含 `dotnet publish` 单目录分发，不依赖用户装 VS；CI 用 `dotnet build`。

## ADR-002 诊断引擎 = 数据驱动的「检查项表」，不是散在代码里的 if

**状态**：已定（2026-10-05）

**背景**：网络故障种类多且随环境变。把检测写死在代码里 = 每加一种故障改一次 UI。

**决定**：每个检测项是一个数据记录：`编号 / 症状 / 检查执行器 / 期望 / 判读 / 修复动作 / 回滚 / 风险级别`。
执行器是少数几个接口（PowerShell 查询、.NET API、TCP 探测、ADB、读配置）。
新增检测项 = 新增一条数据，不改 UI。

**后果**：`research/02-network-diagnosis/02-pc-checklist.md` 的表格列**就是** schema。

## ADR-003 修复一律：先备份 → 显示将要改什么 → 可回滚

**状态**：已定（2026-10-05）

**背景**：改网卡、防火墙、注册表是**破坏性**操作。工具如果直接改，用户失去控制；
路由器设置工具根本改不了，只能解释。

**决定**：每个修复动作必须声明 `备份位置 / 回滚命令 / 风险级别`。
路由器、AP 隔离、VLAN 这类**本机改不了**的，只解释 + 给指引，不假装能自动修。
配对/证书相关配置**只读不改**。

## ADR-004 参数面以「配置文件 + Quest preferences」为唯一真源

**状态**：已定（2026-10-05）

**背景**：参数散在三处：Streamer 的 JSON/注册表、Quest 应用的 preferences、Quest `Mobile.dll` 的 IL 硬上限。
UI 上看起来是「一个设置」，实际来源可能不同（例如码率上限在 IL 里，不在 Streamer JSON 里——
旧 VDH 0.4.x 的 CHANGELOG 已证实这点）。

**决定**：参数模型必须带 `存储位置` 字段；读得到就显示当前值，读不到显示「由头显 IL 决定」并给检测方法。
不做「假设置项」——不要给用户一个改了没用的开关。

## ADR-005 先做 PC 侧检测，ADB 头显侧是第二屏

**状态**：已定（2026-10-05）

**背景**：用户报的故障里，头显找不到 PC / PC 找不到头显这类**网络层**问题占绝大多数，
且不需要连 USB 就能查。ADB 检测需要接线与授权，是第二手证据。

**决定**：首屏 = PC 网络体检（含一键修复）；次屏 = Streamer 参数；第三屏 = 头显（ADB）。
