# 2026-10-05 第三轮：症状语料落地 → 两个新功能

## 这轮做完了什么

1. **社区症状语料**（`research/09-failure-corpus/`，108 行逐字引用，45 个 URL 实测有效）
   - 用户说的「连不上」在工程上是 **23 个不同根因**，我们当时的 18 项检测最多覆盖 9 个。
   - 社区最常给的三个答案在局域网场景**无效或有害**：转发 38810-40、开 UPnP、关防火墙全 profile。
   - 官方 FAQ 是静态清单；「昨天还好好的」这种最常见的求助方式在静态清单下 100% 失效。
2. **`lan-reach` 头显可达性检测**（新，第 19 项）
   - 社区公认的共识诊断法就是「ping 你的头显」，此前只能人做。
   - 头显 IP 在第三屏输入，落盘到 `%AppData%\VirtualDesktopHelper\config.json`。
3. **历史快照 + 变化 diff**（新）
   - 每次运行把「检测项 → 结论」写进 `%AppData%\VirtualDesktopHelper\history\last.json`，上一份留成 `previous.json`。
   - 下次运行直接报「与上次相比有 N 处变化」，并把变了的检测项顶到状态栏。
   - 这条直接对应语料结论 5：静态清单在「昨天还好好的」场景下全绿，此时 diff 是唯一的线索。

## 证据

```
run 1: 18 项全部记为「首次记录」
run 2: 与上次相比没有变化。
run 3: 与上次相比有 1 处变化：
       [lan-reach] 还没填头显 IP，无法测可达性  ->  头显 192.168.11.99 ping 不通
```

可达性检测两分支都实测过：路由 IP（`192.168.11.1`）→ Pass 0 ms；空 IP（`192.168.11.99`）→ Block 并给出 AP 隔离/访客网络指引。

## 下一刀（按语料的重要性排序）

1. **覆盖那 10 个未覆盖的根因**：语料 §S1–S7 已分好类，逐条对应到检测项。头显侧那两类（手部追踪开关、头显 MAC 随机化）是当前架构的结构性盲区——PC 侧检测覆盖不到，需要 adb 在线时的头显侧读取。
2. **纠偏文案进 UI**：7 条社区错误解法目前只在 research 里，应该在相关检测项的指引里直接反驳（例如「本地不需要转发端口」）。
3. **端到端归因报告**（PC + 头显合并一份）。
4. **文档站三段式**（index / checks / faq）。
5. **症状自述入口**：让用户选「看不见电脑」还是「看得见连不上」，直接把范围砍半——社区没人做。
