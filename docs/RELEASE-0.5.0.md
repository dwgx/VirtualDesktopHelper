# VDHelper 0.4.0 —— 别让工具替你说谎（第二版）

0.3.0 之后修的 17 处，收起来是一件事：**生成的结论、措辞、标签，比实测多走了一步。**
这一版的共同形状，先摆出来：

| 地方 | 之前 | 实际发生的事 |
|---|---|---|
| `net-loss` | 「测到 100% 丢包…先分清是 PC→路由器还是 Wi-Fi」 | 头显睡着，**网关那行就写着 0%**，结论把这个证据扔了 |
| `session-stale` | 「当前没有活动会话（也没有残留套接字）」 | 证据下一行就是 `38810 Established → 40.89.161.236:38812` |
| `proc-tuner` | 「命中 6 个（**占 CPU、抢主线程**）」 | 只按**进程名**匹配，从没读过 CPU 时间或线程优先级 |
| `av` | 「已注册杀软：Windows Defender **:: 397568**」 | 那是 `productState` 位掩码，各版本含义不同；判定根本不用它 |
| 面板 | 唯一的阻断项标「**先修**」 | 它是 `lan-reach`，**工具明说自己修不了**——那里没有按钮 |

## 修复：用户会照着做的几处

**写参数被拒时，现在告诉你怎么解。** 以前只有一句「先退出 Streamer 再试」。
现在带真实 PID 给出三种退出方式，并说明本机 Streamer 以管理员权限运行、中途会弹一次 UAC。
配套新增 `--quit-streamer`：优雅关 → 强杀 → **重读进程表确认**。
（提权那一支**未验证**——跑到底会断掉你正在用的串流并弹 UAC，那是先问再做的事。）

**`--report` 不再被 `--selftest` 吞掉。** 以前
`VdHelper.exe --selftest --report issue.md` 只打到 stdout、**不写文件也无警告**——
在求助帖里就是一个空附件。现在报告标志排在前面。

**三个需要管理员的修复不再一声不吭。** `fw-restore-vd`、`svc-start`、`disable-adapter`
都会触发 UAC，现在都标了出来。顺带删掉一个**在说谎的参数**：
`PowerShellRunner.RunAsync(asAdministrator:)` 接收后直接丢弃，而调用方看到它会理所当然以为会提权。

**参数表不再把每个只读键都说成 DPAPI 密文。** 19 个只读键里 18 个确实是配对密文，
`HotKeysEnabled` 不是——以前它也被说成「密文键」。现在按事实区分。

## 修复：写配置不再改写配对密文的写法

`System.Text.Json` 默认会把 DPAPI base64 里的 `+` 转义成 `\u002B`。
**这不是损坏**（解码后逐字节相同，已用真机配置的四段 blob 逐条验证），但写完的文件
不再和 Streamer 写出来的一样，任何按文本判断「配置被动过」的对比都会整片误报。

**这是本工具唯一会改你真实配置的路径，而它此前只验证过拒绝路径**——因为本机 Streamer
一直在跑，每次调用都停在 exit 8。现在把真实配置复制到副本上跑完了整条路径：写入落地、
备份存旧值、14 个键一个没丢、其余 13 键逐键未变、坏 JSON 被拒且文件一字节没动。

## 新增：`tools/capture-discovery.ps1`

项目唯一还开着的那个问题，答案以前是一段散在提示文本里的 pktmon 四步命令。现在是一条命令：
抓 60 秒 → 停 → 转文本 → 判读，判读与抓包分开（`-Analyze` 接已有抓包，不需要管理员）。
判读只认端口 38850，并且把「看到 38850」和「目的地址是广播」分开说；一个包都没有时明确拒绝下结论。

## 修复：issue 模板此前从未生效

`.github/ISSUE_TEMPLATE/bug-report.yml` 用的是旧格式——GitHub 把这里的 `.yml` 当 form，
而 form 必须有 `body:`。整套「附上报告，别手打症状」的指引**一次都没到过用户眼前**。
已转成正规 form，并把那五个「机器上看不到但决定结论」的问题变成真正的输入框。

## 新增两道闸门

- `tools/check-citations.py` —— 出厂的每一条 `File.cs:NNN` 都必须在反编译树里落地
  （当前 **157 条全部可解析**）。出处一旦悄悄失效，论断就变成传说而报告还在照印它。
- `tools/check-issue-form.py` —— 按 GitHub 文档规则校验 issue form。上一条之所以能坏那么久，
  就是因为文件能解析成 YAML、位置也对，**没有任何信号说它从来没工作过**。

## 文档

覆盖度从 **9/23 重核到 15/23**（原判定是对着 18 项检测做的，此后加了 18 项），
剩 2 项，其中「主动探测」记为**有意不做**并附理由：17 字节探测包在协议里是连接前的单播预告包，
PC 侧命中该分支会**关闭本次运行的 38850 监听**。首页「27 vs 35，差额是还没实现的」方向讲反了，已改。

> **为什么是 0.5.0 而不是 0.4.0：** 本仓库同时托管两个产品的发布，`v0.4.0`–`v0.4.7` 属于上一代 VDH。VDHelper 自己的版本线是 0.1–0.3，0.4 这一段被占用了，所以这里跳到 0.5.0，而不是去覆盖一个历史版本。
