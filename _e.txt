fix: a query that failed on stderr still reported Pass

This is the false all-clear again, and it was systematic rather than one check's fault.

Every PsCheck-based check judges with a predicate of the shape "nothing matched => fine". PowerShell
exits 0 even when a cmdlet does not exist: it writes to stderr, prints nothing to stdout, and
reports success. The evidence map captured stdout only, so on any machine missing the cmdlet the
predicate saw an empty list and the check came back Pass — the tool certifying a machine it could not
read.

Verified that PowerShell behaves this way before changing anything:
  Get-ThisCmdletDoesNotExist -ErrorAction SilentlyContinue  ->  stderr has the error, exit 0, stdout empty

Stderr is now part of the evidence, and PowerShellCheck returns Unknown when stderr is non-empty
while stdout is empty, saying plainly that the item was not measured rather than passed.

Proven end to end through the real PsCheck path with a throwaway harness (deleted afterwards): a
check whose judge would have returned true now reports
  status=Unknown
  stderr evidence=Get-ThisCmdletDoesNotExist : ... CommandNotFoundException ...

No regression: 34 checks, 21 pass / 11 warn / 1 block / 1 unknown, verdict still Blocked.
