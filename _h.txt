fix: the sticky table header was hiding the first row of every table on the docs site

Found by rendering the pages instead of only reading their markup, which is how it should have
been checked before: the generated HTML was correct, so grepping it found nothing wrong.

.tblwrap sets overflow-x:auto, which makes it a scroll container. The th rule then set
position:sticky with top:54px — sticky resolves against the nearest scroll container, so the header
pinned itself 54px below the table's own top edge and sat on top of row 1 of every table. On the FAQ
page that hid the entire S1 row, the one symptom class most people arrive looking for; on the checks
page it hid check number 1.

The generated HTML was fine throughout, which is why text extraction over the file had not caught
it: the data was present, only the first row was painted over.

th no longer sticks. tools/capture-docs.ps1 renders a page headlessly so this class of bug is
visible in one command next time.

Verified by re-rendering after the fix: S1 看不见电脑 now shows its full phrase list and judgment
column, and the checks table's row 1 is fully visible.
